# 센서 연결 실패 시 자주 나오는 에러와 대처법

백엔드 실행 시 터미널에 나오는 센서 관련 에러 원인과 해결 방법 요약입니다.

---

## 1. Basler 카메라 (camera)

### 에러 예시
```
Device is exclusively opened by another client.
Connection attempt 1 failed. Error: ...
```

### 원인
- **다른 프로그램이 카메라를 이미 사용 중**입니다. Basler USB 카메라는 한 번에 하나의 프로그램만 열 수 있습니다.

### 해결
- **Pylon Viewer**가 켜져 있으면 종료하세요.
- **DED 제어용 GUI**나 다른 모니터링 프로그램에서 카메라를 쓰고 있으면 해당 프로그램을 종료하세요.
- 그래도 안 되면 USB를 뺐다 꽂거나, PC 재부팅 후 백엔드를 먼저 실행해 보세요.

---

## 2. IPG 레이저 (laser)

### 에러 예시
```
[IPG Laser] 연결 실패: 연결 실패: timed out
⏱️ [laser] 연결 타임아웃
```

### 원인
- 레이저 컨트롤러(192.168.3.230:10001)에 **네트워크로 접속이 안 되는 상태**입니다.

### 해결
- 레이저 **전원**이 켜져 있는지 확인하세요.
- PC와 레이저가 **같은 LAN**에 있는지, **IP 주소**(config에서 설정)가 맞는지 확인하세요.
- 방화벽에서 해당 포트가 막히지 않았는지 확인하세요.

---

## 3. Pyrometer (pyrometer)

### 에러 예시
```
could not open port 'COM12': PermissionError(13, '액세스가 거부되었습니다.', ...)
❌ [pyrometer] 연결 실패
```

### 원인
- **COM12** 포트를 **다른 프로그램이 먼저 사용 중**이거나, 권한이 없습니다.

### 해결
- DED 제어 프로그램, 시리얼 모니터 등 **COM12를 쓰는 프로그램을 모두 종료**하세요.
- 장치 관리자에서 **COM 포트 번호**(COM12가 맞는지) 확인하세요.
- 설정 파일에서 Pyrometer용 **COM 포트**가 실제 연결된 포트와 일치하는지 확인하세요.

## 4. CNC (HXAPI, cnc)

### 에러 예시
- 처음: `⏱️ [cnc] 연결 타임아웃`
- 이후: `[CNC (HXAPI)] 연결됨: 127.0.0.1:3000` → **연결 성공**으로 바뀌는 경우 있음

### 원인
- CNC 서비스(127.0.0.1:3000)가 **늦게 기동**되면 처음 연결 시도 시 타임아웃이 날 수 있습니다.
- 백엔드는 3초 안에 연결을 기다리므로, 서비스가 3초 넘게 걸리면 타임아웃 후 나중에 재연결될 수 있습니다.

### 해결
- **HXAPI/CNC 서비스**가 먼저 실행된 뒤 백엔드를 실행하세요.
- 타임아웃이 나도 로그에 `[CNC (HXAPI)] 연결 성공`이 나오면 실제로는 연결된 상태입니다.

### "retry failed icomGetString Error:-164" 메시지
- **HXApi.dll(CNC 제어기 쪽 라이브러리)**에서 출력하는 메시지입니다.
- CNC가 아직 준비 중이거나 일시적으로 응답이 없을 때 나올 수 있으며, 이후 `retry icomGetString succsses`가 나오면 정상 동작한 것입니다.
- Python 코드가 아니라 **DLL 내부 출력**이라 프로그램에서 제거하거나 숨기기 어렵습니다. 동작에는 문제 없으면 무시해도 됩니다.

## 5. Hik 카메라 (hik_camera_1, hik_camera_2)

- 현재 **비활성화**된 상태일 수 있습니다. 로그에 `연결 안됨: ... hik_camera_1, hik_camera_2`만 나오면 설정에서 의도적으로 빼 둔 경우입니다.
- 사용하려면 설정 및 네트워크(IP/포트)를 확인한 뒤 해당 센서를 활성화해야 합니다.
